Welcome

Hi, I'm Mike

Hi, I'm Mike Karliner. I've made a thing, or to be more precise, Thingstudio.

I've been programming since dinosaurs roamed the earth, or at any rate the mid-1970s, and my first professional job was programming an Intel 8080 in assembler. Since then, I've always had a soft spot in my heart for tiny machines and real-time programming.

Today, I've been known to say that we are in a golden age for those who like to tinker with hardware and software. I must have at least a hundred microcontrollers of various kinds around the room where I'm writing this, and I've bought every Raspberry Pi on the day of release.

There is also a wealth of great open-source projects to help people with microcontrollers and IoT. Some of my favourites are:

  • Node-RED
  • MicroPython (I funded the original MicroPython Kickstarter)
  • Home Assistant
  • Tasmota

So I've finally decided to try to give back a little to the open-source community, by adapting some of the best concepts from these projects and making my own offering.

Thingstudio is an attempt to bring the great programming experience of Node-RED to the world of microcontrollers. It uses as many of Node-RED's concepts and as much of its style as possible, while running on a microcontroller: it compiles Node-RED-style flows to MicroPython and uploads them to the board, where they run persistently without any need for the Thingstudio editor to be connected.

This is my first attempt to make a piece of non-trivial software with AI assistance. I've done my best to supervise the development closely, but if you have a serious objection to AI coding, then this is probably not for you.

Thingstudio is, and will always be, completely open source, with a permissive licence.

Flows

Wire nodes in your browser

Pick nodes from the palette and draw wires between them. A timer, a function and a pin make a blinking LED. Messages flow along the wires, Node-RED style, with the value in msg['payload'].

Built-in nodes cover pins, buttons, sensors, MQTT, HTTP, UDP, displays and touch panels.

inject timer function filter journal clock mqtt publish mqtt subscribe http request udp send wifi status gpio out pwm out ebutton encoder adc bme280 neopixel gui screen gui trend gui button

Every node has a page in the node catalog.

Deploy

Deploy in seconds, then unplug it

The editor compiles the flow to MicroPython and sends it over USB or WiFi. Trying a change takes seconds. There's no firmware to flash.

The flow is saved on the board. Close the editor, unplug the cable, and it keeps running. It starts again after a reset or power cycle.

  • Compiled in your browserTo MicroPython, then to .mpy bytecode.
  • Sent over USB or WiFiOnly the libraries the flow uses go with it.
  • Runs on its ownMicroPython files on the board, nothing else.
Python

Python when you need it, in the same tool

When the built-in nodes aren't enough, write a few lines of Python in a function node. Then write your own nodes, in the same Python. No new language and no firmware build at any step.

  1. Wire built-in nodesMost flows start and end here.
  2. Add a function nodeA few lines of Python using msg['payload'].
  3. Write a custom nodeA .node.json and a .node.py, dropped in a folder. Nothing to rebuild.
  4. Share itOther people drop the same two files into their folder.
Hardware

Designed for the microcontroller

Flows respond to events, and the board waits on many at once. Interrupts, debounced buttons, a rotary encoder, and an analog input that only reports when a reading crosses its bounds are built in.

Each pin and bus is set up once and shared. If two nodes would set up the same pin differently, the compile stops and names both, before anything reaches the board.

interrupt ebutton eswitch encoder adc timer mqtt subscribe

The button, switch and encoder drivers are Peter Hinch's micropython-async primitives.

Screens

Screens and touch

Lay out pages of readouts, labels, bars, lights, buttons and trend charts in the editor. The board draws them in strips of about 5 KB, so a whole frame never has to fit in memory.

The user guide builds a three-page touch display: temperature, humidity and pressure with their history, and a clock, publishing the readings over MQTT.

gui screen gui readout gui label gui bar gui trend gui light gui button gui modal display spi touch panel journal

Tested on the Freenove ESP32-S3 4.0" display with touch, and the CYD's display.

Yours

Local, open, and in plain files

Thingstudio runs on your computer. There's no account and no cloud, and nothing is sent home.

  • Works offlineOnce installed, it needs no internet connection, docs included.
  • Git friendlyFlows and board definitions are plain, indented JSON. Credentials are kept separately, so a committed flow holds no secrets.
  • Apache 2.0Use it, change it and build on it, including in commercial products.
