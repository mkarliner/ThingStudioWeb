Flow programming for microcontrollers

Inspired by Node-RED, ThingStudio gives you a visual flow programming environment for microcontrollers running MicroPython. It runs on ESP32, RP2040 and RP2350 (Raspberry Pi Pico), nRF52840 and STM32. Fully local: no cloud, no account.

Get started Try it in your browser

The demo is the whole editor in a desktop browser, with nothing to install. Build a flow and read the MicroPython it makes. To run a flow on a real board, install ThingStudio.

Free and open source · Apache 2.0 · macOS, Linux, Windows · Source on GitHub

Who it's for

For makers and programmers

ThingStudio is for people who can already program and have used a microcontroller. You don't need an electronics degree, but you should be comfortable wiring a breadboard and typing commands in a terminal.

Coming from another tool? Read what's different for you: Node-RED, MicroPython, or Arduino and C.

A good fit

  • You use Node-RED and want flows on the board itself
  • You write MicroPython and want events without hand-written asyncio
  • You write Arduino or C and your main loop keeps growing

Not a good fit

  • You're learning to program: ThingStudio doesn't teach the basics
  • You don't want to mess with hardware
Yours

Private, open and hackable

ThingStudio is designed to be private, and as open and hackable as possible. The editor sends nothing home, and the online demo runs in your browser and sends nothing either.

  • Fully localDevelopment happens on your computer. There's no cloud service and no account.
  • Works offlineOnce installed, it needs no internet connection, docs included.
  • Git friendlyThingStudio's files, your programs and your board definitions, are plain, indented JSON that you save where you like. They diff cleanly and sit happily in a git repository. Passwords and other credentials are stored separately, so a committed program holds no secrets.
  • Made to be extendedWrite your own custom nodes, and add your own boards and processors. You drop their files into a folder. There's nothing to rebuild.
  • Free and open sourceThingStudio is under the Apache 2.0 license. You can use it, change it and build on it, including in commercial products.
Events

Respond to events, not a growing loop

A typical microcontroller program runs one main loop forever: read the sensors, check the buttons, update the outputs, go round again. Each new job makes the loop longer, and a slow step holds up everything else.

A ThingStudio flow responds to events instead. Each response runs only when its event happens, and the board waits on many events at once. Event-driven programming explains more.

ebutton→ gpio out
timer→ bme280→ mqtt publish
mqtt subscribe→ function→ neopixel

Three chains in one flow. A button press lights an LED, a timer reads a sensor and publishes it, and a message from the network sets a colour. None waits for the others.

Architecture

The big split

In Node-RED, the editor and the runtime are one program on one computer. ThingStudio splits them. You build the flow on your computer; ThingStudio compiles it to MicroPython and sends it to the board over USB or WiFi.

The flow is saved on the board. Close the editor, unplug the cable, and it keeps running. It starts again after a reset or power cycle. A change is a new deploy, not a firmware build, and takes seconds.

Your computerThe editor, in your browser. Compiles the flow to MicroPython, then to .mpy bytecode.
USB or WiFi
The boardMicroPython, the flow, and only the libraries it uses. Nothing else.

A blank board? Tools → Install firmware… writes MicroPython onto ESP32 and Pico boards from the editor.

Hardware

It knows your board

Boards can have a definition file, which lists the board's pins, its LED, which pins are reserved and why, and which pins each SPI and I2C bus can use. Pins… in the editor shows it as a pin cheat sheet, and for boards like the Pico lays out the header the way the board looks.

ThingStudio comes with definitions for a handful of boards, and for the common ESP32 and RP2 chips. For anything else, add your own: a short JSON file. Give an AI assistant the board's pinout and an existing file, and it does this very well. Check the result against the datasheet.

Every pin in a flow is checked against the board it's for. Each pin and bus is set up once and shared. If a pin doesn't exist, would crash the board, or two nodes would set it up differently, the compile stops and says why, before anything reaches the board.

Flows respond to events, and the board waits on many at once: interrupts, debounced buttons, a rotary encoder, an analog input that only reports when a reading crosses its bounds.

interrupt ebutton eswitch encoder adc gpio out pwm out bme280 neopixel timer

The button, switch and encoder drivers are Peter Hinch's micropython-async primitives.

Flows

Node-RED's model, at microcontroller scale

Pick nodes from the palette and draw wires between them. Messages travel along the wires, with the value in msg['payload'], as they do in Node-RED. A timer, a function and a pin make a blinking LED.

Built-in nodes cover pins, buttons, sensors, MQTT, HTTP and UDP. When they aren't enough, write MicroPython in a function node, or package it as a custom node with its own place in the palette.

inject timer function change filter delay journal ntp mqtt publish mqtt subscribe http request udp send wifi status http in udp receive debug

Every node has a page in the node catalog.

Hardware

Microcontrollers it runs on

What matters is the processor. If your board has one of these chips and runs MicroPython, pick the chip from the Board menu and start.

Boards with a definition also get a pin cheat sheet: their own pins named, such as the LED, and the reserved pins marked. Supported hardware lists them, with the sensors and displays that have built-in nodes.

Welcome

Why I made ThingStudio

Hi, I'm Mike Karliner.

I've been a huge fan of flow programming since the early days of Node-RED.

Equally, I've been keen on MicroPython since it came out, and in fact I backed the original Kickstarter way back in 2013.

So, I thought, why not combine the best of both worlds?

ThingStudio is my attempt to do just that. Obviously, it's not an exact copy: its native language is MicroPython, for a start, and it's running on bare metal.

It is, and will stay, open source under a permissive licence.

Mike

Status: beta

It works on my bench, and I've checked it runs on every board I've been able to get my hands on. But I'm not the best person to find the rough parts, especially in getting started. So it's in beta: it works, and now it needs people other than me to set it up and use it from the docs alone. Expect rough edges, and gaps in the docs that I just can't see.

Testers wanted

I'm looking for some brave souls to try the onboarding. The idea is that someone with some microcontroller or Node-RED experience can go from a blank board to a blinking LED, installing everything on the way, MicroPython included, in about 15 minutes. All you need is an ESP32 or a Raspberry Pi Pico.

Start at Getting started, and tell me how it went: which board and computer, how long each step took, and every place you stopped, guessed or swore. All polite feedback very gratefully received, in an onboarding report on GitHub, or by email if you'd rather keep it private: mike@minus1.com.
